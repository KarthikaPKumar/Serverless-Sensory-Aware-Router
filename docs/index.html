UNDER THE SURFACE

Understand the
trade-off.

This demo computes routes on a fixed, synthetic network. Change a preference and see which path becomes a better match.

How are routes selected?

Dijkstra's algorithm finds the path with the lowest total cost. The shortest-time route uses walking minutes only. Your preference route adds a penalty for the signals you care about.

segment cost = minutes × (1 + crowd weight × crowd / 100 + noise weight × noise / 100 + light weight × light / 100)

Weights run from 0 to 5. Signal values run from 0 to 100. Higher signals mean more exposure. These are demo inputs, not measured conditions.

What do the comparison numbers mean?

The three exposure scores are averages weighted by time spent on each segment. They describe this synthetic journey, not a safety rating, accessibility certification or a prediction about a real street.

Where does the data come from?

The demo uses 10 invented places and 14 connections with fixed sample values. The repository also contains the original City of Melbourne ingestion utilities and PostGIS schema, but this published demo does not connect to that database. No ML model or live forecasting is used.

What would a live version need?

A separately hosted API, a geographic routing provider, a PostGIS database and a monitored ingestion pipeline. Real observations would need timestamps, coverage checks and missing-data handling before they could inform route comparisons.
